# Важно: продакшен-конфигурация этого проекта

Сайт «Зрелая красота» — https://women.an51.su (репозиторий
`vknmurm-star/site-001`, ветка `main`). Он развёрнут на собственном VDS
**noemi** (Selectel, `selectel.an51.su`), не на Vercel, и использует
переменные окружения для продакшен-настроек. При внесении изменений
СОХРАНЯЙ описанную ниже логику — не хардкодь значения, которые должны
браться из окружения.

Старый сервер `kvm.an51.su` сайты больше не хостит (там остался только VPN) —
деплоить туда ничего не нужно.

## 1. Переменные окружения (.env.local на сервере, НЕ в git)

Файл `/var/www/site-001/.env.local` на noemi содержит:
```
GITHUB_OAUTH_CLIENT_ID=...
GITHUB_OAUTH_CLIENT_SECRET=...
SITE_URL=https://women.an51.su
```

Сайт работает на стандартном 443 порту (HTTPS через certbot), домен без
порта в конце.

Файл в `.gitignore`, через git не синхронизируется. Значения на сервере уже
настроены правильно — трогать их через код не нужно. Ночной бэкап noemi
(restic) включает этот файл.

## 2. src/app/api/auth/route.ts

Этот файл ДОЛЖЕН брать базовый URL сайта из переменной окружения `SITE_URL`,
а НЕ вычислять его из `req.nextUrl.origin`. Причина: сайт работает за nginx
reverse proxy, и `req.nextUrl.origin` внутри Next.js видит только внутренний
адрес (`localhost:3000`), а не реальный внешний домен и протокол — из-за
этого OAuth redirect_uri ломается (в частности, может подставиться `http://`
вместо `https://`, если nginx не прокидывает `X-Forwarded-Proto`).

Правильная логика:
```typescript
const siteUrl = process.env.SITE_URL || req.nextUrl.origin;
const redirectUri = `${siteUrl}/api/callback`;
```

Если будешь переписывать этот файл — сохрани эту логику (fallback на
`req.nextUrl.origin` можно оставить для локальной разработки, но
`SITE_URL` должен иметь приоритет).

## 3. public/admin/config.yml

Секция `backend:` должна содержать:
```yaml
backend:
  name: github
  repo: vknmurm-star/site-001
  branch: main
  base_url: https://women.an51.su
  auth_endpoint: api/auth
```

Если пересоздаёшь или регенерируешь этот файл — не оставляй
плейсхолдеры вида `YOUR-DOMAIN.example` или неправильный `repo` (это уже
случалось при первой генерации). Всегда указывай реальный `repo` и
`base_url` выше.

## 4. Процесс деплоя (автодеплой по cron, `deploy.sh` больше нет)

Скрипта `deploy.sh` на сервере нет. Деплой идёт автоматически:

1. Правки вносятся локально (или Decap CMS коммитит прямо в GitHub).
2. `git pull` перед работой, затем `npm run lint` и `npm run build` локально.
3. `git add` нужных файлов → `git commit` → `git push` в `main`.
4. Каждые 2 минуты cron на noemi запускает
   `/root/bin/site-autodeploy.sh /var/www/site-001 main site-001 3000`.
   Скрипт: `git fetch` → только fast-forward → `npm ci`, если изменился
   `package-lock.json` → `npm run build` (при падении один повтор) →
   `pm2 restart site-001` → проверка ответа `http://127.0.0.1:3000/` →
   IndexNow. Сборки разных сайтов идут по общей очереди (одновременно
   только одна), так что на сборку может уйти несколько минут.
5. Если сборка упала дважды, скрипт откатывается на прежний коммит, а
   упавший коммит запоминает и повторно не собирает, пока в `main` не
   появится новый.

Как проверить результат (ждать строку `=== готово <sha>`):
```
ssh selectel 'tail -15 /var/log/autodeploy-site-001.log'
```
Маркеры проблем в логе: `!!! сборка ... упала дважды — откат`,
`!!! ПЕРЕСБОРКА ПОСЛЕ ОТКАТА ТОЖЕ УПАЛА` (нужен человек).

**Правок прямо на сервере не вносить**: автодеплой делает только
fast-forward, локальные изменения в `/var/www/site-001` его ломают.
Не переименовывай процесс PM2 `site-001` и не меняй порт 3000, на котором
слушает Next.js, без явной просьбы. `pm2 restart` сам по себе страницы не
пересобирает (SSG), нужна полная сборка — её делает автодеплой.

## 5. Статическая генерация и абсолютные URL (http/https)

Главная, страницы категорий и статей (`/`, `/categories/[slug]`,
`/articles/[slug]`) — статические (SSG, помечены `●` в выводе `next build`).
Это значит:

- Next.js рендерит их ОДИН РАЗ на этапе `npm run build`, а не при каждом
  запросе. Заголовки запроса (`req.headers`, `req.nextUrl.origin`) на этих
  страницах вообще не читаются и не могут повлиять на итоговый HTML —
  значение `SITE_URL` "запекается" в статическую страницу на момент сборки.
  Локально, без `SITE_URL`, canonical в собранном HTML будет
  `https://example.com/...` — это нормально, на сервере берётся реальный.
- Единственный источник правды для абсолютных URL — константа `SITE_URL` в
  `src/lib/site.ts` (`process.env.SITE_URL`). Через неё (или через хелпер
  `absoluteUrl()` из того же файла) строятся: `metadataBase`,
  `<link rel="canonical">`, `og:url`, `og:image`, twitter-теги, все
  `url`/`image`/`logo` в JSON-LD, `sitemap.xml`, `robots.txt`.
- Header и Footer (`src/components/Header.tsx`, `Footer.tsx`) намеренно
  используют ТОЛЬКО относительные `href` (`/about`, `/categories/skincare`
  и т.д.) через `next/link` — это правильно, менять на абсолютные URL не
  нужно. Браузер сам резолвит относительную ссылку в текущий протокол
  страницы.

**Если на живом сайте статьи открываются по `http://`, а главная — по
`https://` (или наоборот)** — это НЕ баг в коде страниц. Единственное, что
реально читает заголовки запроса "на лету" — это `src/app/api/auth/route.ts`
и `src/app/api/callback/route.ts` (OAuth для Decap CMS), и они уже
приоритетно берут `SITE_URL` из окружения.

Разбираться нужно на уровне nginx (`/etc/nginx/sites-available/women.an51.su`):
1. nginx делает безусловный 301-редирект с `http` на `https` для ВСЕХ путей
   (отдельный `server { listen 80; }` блок с
   `return 301 https://$host$request_uri;`).
2. В блоке проксирования на Next.js (порт 3000) есть
   ```
   proxy_set_header Host $host;
   proxy_set_header X-Forwarded-Proto $scheme;
   ```
   Это нужно для корректной работы OAuth-редиректов (см. пункт 2 выше), даже
   если на статические страницы это не влияет.
3. После правок nginx — `nginx -t && systemctl reload nginx`. Пересборка
   сайта для этого не требуется, если `SITE_URL` в `.env.local` верный
   (`https://women.an51.su`, без порта).

## 6. SSH-доступ к серверу

Доступ по SSH настроен, беспарольный (по ключу). В `~/.ssh/config` есть
алиас (он же `noemi`, `selectel.an51.su`):
```
ssh selectel
```
Это `root@139.100.232.115` (сервер noemi), рабочий каталог сайта —
`/var/www/site-001`, процесс PM2 — `site-001`.

**Важно — сервер общий для многих сайтов** (women, men, finance, coffee,
genhome, ai, beauty/market-store, cartime, shelko, uspr и др., у каждого
свой PM2-процесс, порт и nginx-конфиг). При правках nginx или системных
настроек будь аккуратен, чтобы не задеть остальные:
- перед любым `systemctl reload nginx` — сначала `nginx -t`;
- после reload — проверь, что сайты отвечают 200, как минимум:
  ```
  for d in women men finance coffee genhome ai beauty; do
    echo "$d: $(curl -s -o /dev/null -w '%{http_code}' https://$d.an51.su/)"
  done
  ```
- памяти на сервере немного: не запускай тяжёлые сборки вручную параллельно
  с автодеплоем, не добавляй лишних процессов без нужды.

Не перебирай имена пользователей залпом: на сервере работает fail2ban
(`sshd`), серия неудачных попыток банит IP. Подключайся только через алиас
`selectel` (пользователь `root`). Хост-ключ `kvm.an51.su` менялся в
октябре 2026, при предупреждении `REMOTE HOST IDENTIFICATION HAS CHANGED`
не обходи проверку, а сообщи владельцу.

## 8. Контент: статьи в `content/articles/*.mdx`

**Frontmatter — все строковые значения в двойных кавычках**, включая
`title`, `description`, `category`, элементы `tags`, `coverLabel`,
`coverImage`, `coverImageAlt`, `seoTitle`, `seoDescription`:
- **`date` обязательно в кавычках** (`date: "2026-10-15"`). Без кавычек
  gray-matter превращает дату в JS-объект `Date`, что ломает
  `article:published_time` (`[object Object]`) и `<time dateTime>`. Защита в
  коде есть (`normalizeDate()` в `src/lib/articles.ts`), но кавычки в
  исходнике обязательны.
- Любая строка с двоеточием и пробелом внутри (`слово: слово`) без кавычек
  ломает YAML и сборку. Проще всего кавычить всё.
- Образец формата — любая недавняя статья, например
  `content/articles/kozha-v-otopitelnyy-sezon.mdx`.
- Категории (slug): `skincare` (Уход), `makeup` (Макияж), `style` (Стиль),
  `wellness` (Самочувствие). Держать баланс по разделам.

**Тон:** без давления и «антивозрастной» паники, без обещаний вернуть
молодость, без медицинских советов (особенно в «Самочувствии»).

**Перед публикацией** сверять тему с уже опубликованными статьями; при
сильном пересечении — сообщить владельцу до публикации.

**Перелинковка:** блок «Читайте также» формируется автоматически (3 самые
свежие статьи той же категории), поэтому в тексте добавляй контекстные
ссылки `[текст](/articles/slug)` минимум на одну близкую статью.

**Обложки:** генерируются через `content-factory-001/generate_image.py`
(fal.ai, стилевые требования в `styles.py`: документальный кадр, без
глянца, без зеркал, без крупных баночек с надписями). Сохранять в
`public/images/uploads/image_NNN.jpg`, прописывать `coverImage` и
содержательный `coverImageAlt`.

**Не добавлять** блок подписки на рассылку — на сайте он удалён намеренно.

**Локальные настройки Claude** (`.claude/settings.local.json`) в `.gitignore`,
в репозиторий не коммитятся.
